===== FIX VERIFICATION: zero-downtime rolling update =====
Fix: preStop (sleep 8) + terminationGracePeriodSeconds: 30 + SIGTERM handling

Measurement method matters. A first attempt probed through
'kubectl port-forward service/jobs-service', which reported 25/85 failures --
but that is an artifact: port-forward pins to ONE backing pod, so the forward
breaks when that pod is replaced (it also never observed v2 at all: v2=0).
The probe below runs INSIDE the cluster against the Service, so it sees the
same load balancing real clients do.
